## Findings and repairs

| Area | Confirmed defect | Correction |
| --- | --- | --- |
| Episode evidence | Reported success, recovery counts and detection ratios could contradict recorded transitions. Boolean counter aliases and malformed action/state records were accepted. | Validate canonical counters, final success, legal actions, finite observed states, alarm time/matching, trigger consistency and complete recovery accounting. |
| Study configuration | Boolean schema versions, duplicate keys, unused fields and incomplete declarations were silently accepted. | Strict finite JSON and complete typed configuration with disjoint model/fit/evaluation seeds. The Python runner also validates before writing or training. |
| Existing results | Calling the Python runner directly could replace existing records despite the CLI's protection. | Require an empty ordinary output directory at the API boundary. |
| Observation integrity | Mutating returned event dictionaries could rewrite the environment's internal fault evidence. | Return detached event copies. |
| Memory and calibration | Boolean rewards and malformed training/calibration metadata could enter saved evidence. | Validate rewards, counts, seed, training settings, sample counts and disjoint episode partitions before saving. |
| Checkpoints | Unknown fields could silently carry unused conflicting settings. | Validate supported fields and bounded ordinary local files before restricted loading. Existing schema 0 and 1 models remain supported. |

Additional regression coverage checks altered trial identities, omitted methods or
histories, memory-credit mismatches, checkpoint/provenance conflicts, corrupt
observations, unsupported file sets and runtime configuration mutations.

## Evidence audit

The new verifier binds the rows to the supplied complete plan instead of inferring
completeness only from observed rows. This catches removing every observation of
a model, method, repetition or history. It verifies the recorded execution order,
root/episode seed mapping and counterbalanced condition orders. Fitting outcomes
reconstruct the saved candidate and task-reward memories. Aggregates and paired
bootstrap intervals are recomputed from all declared evaluation rows.

Optional simulator replay follows the recorded actions and checks actual action
results, state vectors and generated fault events. The 14,700 archived evaluation
episodes plus 2,940 fitting episodes replay 113,047 actions. This uses the same
simulator, not a separate physics implementation. It cannot establish that the
recorded policy actually chose those actions or that a real robot would do so.

The archived development split contains 5,880 evaluation and 1,176 fitting episodes.
The two archives together contain 24,696 episodes. The original configurations,
checkpoints, compressed traces, memory snapshots and results are not overwritten.

## Interpretation

The previously reported result remains a negative comparison for learned
monitoring and ranking in this ideal-state symbolic environment. Simpler controls
match the learned methods' success/action counts, and the tested memories add cost.
The audit does not add independent training seeds, change the evaluation criteria,
or turn repeated runs into additional statistical observations.

A separately run original-head experiment and a fresh candidate experiment use
the same current Python/PyTorch environment to test behavioural compatibility.
Do not require bitwise training equality to the older archived runtime. Inspect
recorded versions and source hashes; cross-platform numerical equivalence is not
promised. Held-out here means the original declared split, not new data unknown
to this later audit.
